# Планы развития

## Что уже готово

**MVP выполнен в проверенном сценарии ChatGPT через NextDNS + GeoHide.** Контроллер запускается в GitHub Actions, читает официальные hosts, проверяет маршруты, синхронизирует DNS и сохраняет зашифрованное состояние. Подтверждены повторный запуск без изменений, работа между runners, расписание и доступ с устройства. [Матрица приёмки и её ограничения](acceptance.md).

Новый DNS-адаптер и новый relay подключаются независимо. Собственный relay описывается manifest; наличие одного IP VPS без работающего relay недостаточно. AdGuard Home и Technitium пока доступны только для чтения.

## Приоритеты после MVP

Безопасные [причины сбоев в Summary](../operations/diagnostics.md), структурированная двуязычная документация, [workflow релиза](releases.md), changelog и [руководство обновления форка](../operations/upgrading.md) реализованы. Первый релиз [v0.1.0](https://github.com/r4mdevelopment/SmartGate/releases/tag/v0.1.0) опубликован; workflow выпуска и пакеты проверены.

Следующие направления остаются планами:

| Приоритет | Доработка | Результат для пользователя |
| --- | --- | --- |
| 2 | Проверка полноты готовых наборов сервисов | Для каждого набора отделять проверенные сценарии от предположений, подтверждать вход, сообщения и работу файлов; не включать все сервисы автоматически |
| 2 | Процедура смены ключа шифрования | Проверяемый переход со старого ключа на новый с резервной копией, закрытым журналом и read-back. Сейчас произвольная замена Secret делает прежнее состояние нечитаемым |
| 2 | Проверки восстановления на отдельной инфраструктуре | Дополнить имитацию сбоев тестами безопасного восстановления из backup и обновления версии; действующий профиль для экспериментов не используется |

Дополнительные DNS-адаптеры могут развиваться через вклад сообщества. Они требуют собственной совместимости API/DNS и доказательств владения записями; успешный mock-тест или один запуск harness не включает рабочие записи автоматически.

## Эксплуатационные ограничения

- Периодические проверки не дают мгновенного переключения. На задержку влияют GitHub Actions, внешний relay, API и DNS-кеши устройства.
- GitHub может задержать schedule или отключить его при условиях, описанных в [руководстве Actions](../operations/actions.md#неуспешный-запуск-и-квоты). Проверка остановленного расписания требует наблюдения вне самого остановленного workflow; отдельного внешнего мониторинга в проекте нет.
- Проверка TLS из runner не доказывает работу приложения из каждой пользовательской сети. Новые сервисы и собственный VPS требуют проверки на устройстве.
- Первоначальная настройка остаётся ручной через GitHub. Локальная расшифровка подробного отчёта пока требует Python.

Сначала улучшаются диагностика и воспроизводимость установки, затем расширяется проверенная область применения. Новые направления не должны обходить ownership, явное разрешение записей или шифрование.
