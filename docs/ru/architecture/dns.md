# DNS-слой

DNS-провайдер публикует ответы для выбранных доменов. Relay передаёт трафик к сервису, а SmartGate проверяет доступные маршруты и управляет изменениями DNS через адаптер.

Общий интерфейс включает чтение записей, создание, удаление и замену. Формат API, авторизация и особенности идентификаторов принадлежат конкретному адаптеру. Текущая рабочая интеграция описана в [руководстве NextDNS](../providers/dns/nextdns.md).

## Проверка DNS

Общий проверяющий компонент обращается к HTTPS DoH выбранного назначения. Он не меняет DNS устройства и не получает API credentials. Перенаправления и системные proxy отключены; адрес не допускает встроенных credentials, query или fragment.

Для каждого домена A должен содержать ровно выбранный IPv4. AAAA, HTTPS и SVCB должны возвращать пустой успешный ответ, чтобы клиент не обходил IPv4-маршрут. Проверяются ID вопроса, имя, тип, код ответа, полнота и ограничение времени; неожиданный CNAME не считается подтверждением.

## Назначение и возможности

Назначение описывает тип провайдера, API origin, scope и DoH. Его fingerprint отличает серверы и профили даже при одинаковом имени экземпляра. Возможности адаптера отдельно показывают стабильность ID, семантику поддоменов и допустимость рабочего применения. Наличие общего интерфейса само по себе не доказывает эти свойства. NextDNS зарегистрирован с production apply; AdGuard Home и Technitium зарегистрированы как read-only reference с непроверенной семантикой поддоменов и identity по значению. Live compatibility harness не меняет эти встроенные возможности.
