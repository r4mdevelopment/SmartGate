# Выбор маршрутов

SmartGate выбирает один IPv4 endpoint для каждого явно известного домена. Routing получает каталог сервисов, снимки relay-источников, результаты TLS-проверок и сведения о принадлежащих SmartGate записях. Выбор не выполняет сетевых запросов и не изменяет DNS.

## Порядок выбора

| Условие | Решение |
| --- | --- |
| Текущий owned endpoint присутствует в свежем источнике, TLS прошёл, политика прежняя | Сохранить текущий маршрут |
| Текущий endpoint получил итоговый failed, есть проверенный резерв | Выбрать резерв |
| Текущий endpoint есть в свежем источнике, политика прежняя, проверка дала unknown | Сохранить текущий маршрут с degraded-причиной |
| Текущего endpoint нет в свежем источнике, есть проверенная замена | Выбрать замену |
| Изменена политика, есть проверенный endpoint в новом порядке | Повторно выбрать маршрут |
| Нет свежего проверенного endpoint | Сохранить owned маршрут с degraded-причиной; новый домен отметить unavailable |
| Owned домен явно отключён или исключён из каталога | Отметить remove для последующей проверки правил удаления |

Новый endpoint выбирается по порядку провайдеров в `provider_order`, затем по числовому `priority`, затем по числовому IPv4. Меньший priority предпочтительнее. Время TLS-соединения не участвует в сортировке: задержка со стороны контроллера не описывает задержку клиента.

`failed` — итог всей ограниченной проверки HealthChecker. Конфликтующие результаты одного endpoint считаются unknown. Отсутствие подтверждённого ownership не позволяет сохранять запись только на основании кеша selections.

## Свежесть и обязательные домены

Контроллер передаёт один timestamp начала запуска в получение источников, валидацию и routing. Свежий snapshot имеет этот timestamp и не помечен stale. Snapshot из предыдущего запуска не разрешает создание или замену. При сбое получения источника валидный кеш возрастом до 24 часов используется только для сохранения маршрута и диагностики. Более старый snapshot отвергается до routing. Даже без допустимого snapshot существующие owned записи сохраняются с degraded-причиной; новые маршруты из кеша не создаются.

TLS-результат должен принадлежать текущему запуску: `checked_at` находится между началом запуска и его пределом в 20 минут. Старый успешный TLS-результат нельзя использовать как новое подтверждение доступности.

Отсутствие обязательного домена в свежих допустимых источниках блокирует новые маршруты всего сервиса. Неудачная TLS-проверка обязательного домена отмечается как required failure; необязательного — как optional failure. Отдельная метрика доступности считает долю доменов сервиса с подтверждённым маршрутом без degraded-причины; в знаменатель входят также owned и известные по сохранённым источникам домены. Порог для каждого включённого сервиса — не менее 85%, и все required domains должны быть подтверждены. Сохранённый degraded-маршрут не считается доступным. Прикладной доступ сервиса требует отдельной проверки даже при успешном TLS.

Routing использует только объявленные источниками домены, обязательные домены каталога и уже принадлежащие SmartGate записи. Поддомены автоматически не добавляются.

## Смена relay-провайдера

Для собственного relay подготовьте manifest по [формату провайдеров](../providers/relays.md) и укажите его ID первым в `provider_order`. Изменение порядка меняет routing policy digest и разрешает повторный выбор после успешной проверки нового endpoint.

Например, переход от `["geohide-ru", "own-nl"]` к `["own-nl", "geohide-ru"]` отдаёт предпочтение собственному relay. Без проверенной замены текущий owned маршрут сохраняется с degraded-причиной. DNS-слой получает ту же модель `DesiredRewrite(domain, ipv4)`, независимо от происхождения endpoint.

## Граница применения

`select_routes` возвращает решения select, retain, unavailable или remove. `to_desired` преобразует select/retain в целевые IPv4 rewrites; остальные решения в этот список не входят.

Отсутствие домена в целевом списке не является запросом на удаление. Remove — отдельное намерение, которое слой синхронизации должен проверить по ownership, preconditions и `allow_prune`. Долговременное состояние и журнал реализованы в [StateStore](../operations/state.md). Применение DNS-операций и восстановление после сбоев остаются задачей отдельного слоя reconcile.
