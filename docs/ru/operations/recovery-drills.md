# Проверка восстановления отдельно от рабочего DNS

Проверка подтверждает, что обновление сохраняет ownership, а проверенная резервная копия позволяет восстановить состояние. Для этого не нужно ломать рабочую установку или менять DNS устройств.

## Отдельное окружение

Создайте новый пустой тестовый DNS-профиль и отдельную ветку состояния. Его ID не должен совпадать ни с одним действующим профилем устройств. Используйте независимые временные ключи. Запишите созданные ID профиля и ветки, чтобы удалить только их. Вместе с зашифрованным backup приватно сохраняются репозиторий, ветка, DNS-привязка и точная revision.

## Сценарии

1. Создать одно тестовое DNS-правило, сохранить его точный record ID, список DNS-записей и исходное состояние.
2. Проверить поддерживаемый переход ownership-формата со schema 1 на schema 2: record ID и содержимое не меняются, старый путь удалён, новая привязка назначения читается. Это проверка миграции состояния, а не совместимости любых будущих версий пакета.
3. Выполнить предварительную проверку смены ключа и применение. Прочитать backup старым ключом, текущий документ новым. Список DNS-записей должен остаться прежним.
4. Изменить только тестовые метаданные состояния. Расшифровать backup, проверить назначение и ownership по текущему снимку DNS, затем сохранить восстановленный документ через CAS с текущей revision и ключом. После чтения весь документ должен совпадать с backup, кроме новой revision. Историю Git не сбрасывать; нечитаемое состояние не считать отсутствующим.
5. На integration fixtures проверить обычный sync без изменений после смены ключа, незавершённые журналы, повреждённое шифрование, конфликты и потерянное подтверждение без повторных mutations. Эти сбои имитируются офлайн, а не вызываются в рабочей установке.
6. Удалить только тестовое правило/профиль и тестовую ветку. Повторно прочитать рабочий профиль и состояние, подтвердить их неизменность.

Автоматические сценарии на fixtures:

```bash
python -m pytest tests/integration/test_state_key_rotation.py tests/integration/test_encrypted_lifecycle.py -q
```

Проверка на отдельной живой инфраструктуре дополняет тесты. Она не разрешает production-записи reference DNS-адаптерам и не подтверждает все возможные сбои. Восстановление рабочей установки по-прежнему требует осмотра и [инструкции](runbook.md).
