# Смена ключа шифрования состояния

`state-rotate` перешифровывает сохранённое Git-состояние без изменения DNS-записей. Команда не заменяет GitHub Secrets и не перешифровывает старые коммиты и отчёты. Старый ключ нужен для чтения истории и резервной копии.

## Подготовка

Используйте версию контроллера с `state-rotate`. Сохраните оба ключа в защищённом менеджере паролей. Требуются schema 2, совпадающее DNS-назначение и отсутствие незавершённого журнала. Допускаются `verified`, `rolled_back` или отсутствие журнала. Ветка должна содержать ровно один документ состояния; дополнительные файлы state блокируют переход.

Установите `SMARTGATE_APPLY_ENABLED=false` и дождитесь завершения текущего sync. Не запускайте другие команды с записью до окончания смены ключа и Secret. Workflow использует общую с sync группу concurrency. Настройки DNS устройств и действующие DNS-записи остаются прежними.

## Переход через GitHub Actions

1. Не меняйте `SMARTGATE_STATE_ENCRYPTION_KEY`. Добавьте временный Environment Secret `SMARTGATE_STATE_NEW_ENCRYPTION_KEY`: другой ключ из 32 случайных байтов в стандартном Base64. Не вводите ключи в поля запуска workflow.
2. На основной ветке запустите **SmartGate sync**, `command=state-rotate`, `apply=false`; остальные параметры оставьте по умолчанию. Проверяются чтение старого состояния, новый ключ, завершённый журнал, назначение и владение DNS-записями. Предварительная проверка не создаёт backup и ничего не записывает.
3. После успешной проверки запустите **`command=state-rotate`, `apply=true`**. Команда создаст новый файл зашифрованной резервной копии без перезаписи существующего, проверит его, обновит состояние через CAS и подтвердит чтение точного коммита новым ключом. При неизвестном результате запись автоматически не повторяется.
4. Скачайте artifact запуска и сохраните `before.enc.json` в отдельном защищённом хранилище. Копия читается старым ключом. Artifacts удаляются через семь дней; одна история Git не заменяет независимую копию.
5. Замените `SMARTGATE_STATE_ENCRYPTION_KEY` сохранённым новым ключом вручную в GitHub. Удалите временный Secret и выполните `command=doctor`, `apply=false`: обычное чтение и DNS должны работать. Подробный отчёт самой ротации читается старым ключом; последующие отчёты — новым.
6. Только после успешной проверки верните прежнее значение `SMARTGATE_APPLY_ENABLED`.

Между перешифрованием состояния и заменой Secret обычные команды со старым ключом остановятся. В это время scheduled doctor также может завершиться ошибкой. Не выполняйте bootstrap и не удаляйте состояние, чтобы обойти ошибку. Обычные команды не подбирают временный новый ключ автоматически.

## Неопределённый результат

Оставьте автоприменение выключенным, сохраните оба ключа и backup. Проверьте текущую ветку и документ соответствующим ключом: сначала определите, старое или новое шифрование сейчас используется, затем меняйте основной Secret. Потерянное подтверждение не является основанием повторять `apply`. Подтверждённая запись с неуспешной последующей проверкой DNS также требует осмотра, хотя сама ротация DNS не меняет.

Чтобы вернуться к старому ключу после завершённого перехода, выполните ту же проверяемую процедуру с сохранённым старым ключом в роли временного нового. Создаётся новый коммит; Git ref не сбрасывается. Восстановление backup требует проверки привязки репозитория, ветки и назначения, ownership, журнала и текущей revision. [Проверки восстановления](recovery-drills.md).

Без старого ключа старые отчёты и backup не читаются. Смена ключа не стирает историю и не меняет API key DNS-провайдера.
