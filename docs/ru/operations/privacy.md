# Приватность состояния и отчётов

SmartGate хранит настройки маршрутов и журнал изменений DNS. Это не история сайтов, открытых пользователем: контроллер не получает браузерный трафик или журнал DNS-запросов устройств. Журнал нужен, чтобы после прерывания понять, какие операции уже выполнены, сохранить владение записями и безопасно выполнить recovery или rollback.

## Что защищено

| Данные | Хранение |
| --- | --- |
| Ownership, маршруты, снимки источников, план и журнал | Весь документ зашифрован при live Git-хранении; ветка по умолчанию — `smartgate-state` |
| Подробный отчёт: домены, IP, проверки и ошибки | Зашифрованный artifact `report.enc.json` |
| Summary, stdout, `report.json`, `report.md` в Actions | Статус, агрегаты и фиксированные категории ошибок |
| Резервная копия перед сменой ключа | `before.enc.json` в artifact ротации, зашифрованный старым ключом |
| Конфигурация, каталог сервисов и manifest, пути файлов, размеры ciphertext, формат envelope, время и авторство коммитов | Видны читателям репозитория |
| Локальное файловое состояние и обычные локальные отчёты | Не зашифрованы; храните вне Git и ограничьте доступ |

AES-256-GCM использует новый случайный nonce при каждом сохранении и проверяет целостность при чтении. State привязан к репозиторию, ветке и экземпляру назначения; report — к репозиторию, номеру запуска и попытки Actions. Подмена, другой ключ или неверная привязка блокируют чтение. Непрочитанное состояние нельзя считать отсутствующим и заново присвоить DNS-записи.

## Служебные логи GitHub

Сохраняйте DNS profile ID, namespace и адреса API/DoH в одноимённых Environment **Secrets**, а не Variables. Workflow предпочитает Secrets, и GitHub маскирует их в служебном выводе env ещё до запуска Python. Приватная проекция контроллера не может удалить данные, уже напечатанные GitHub. Старые Variables поддерживаются для перехода и могут раскрывать значения в логах. Простого создания неиспользуемого Secret недостаточно: workflow должен прочитать его.

## Подготовьте ключ

Добавьте Environment Secret **`SMARTGATE_STATE_ENCRYPTION_KEY`**: 32 случайных байта в стандартном Base64. Он независим от DNS API key. Сгенерируйте ключ на доверенном устройстве и сразу сохраните его в защищённом менеджере секретов; перенесите значение непосредственно в GitHub Secret и независимую защищённую резервную копию.

Не выводите ключ в терминал и не передавайте через workflow, коммит, Issue или публичный чат. Генератор должен выдавать именно 32 криптографически случайных байта с кодированием Base64, а не обычный пароль из 32 символов. Сам контроллер продолжает работать в Actions.

Каждая установка и каждый fork получают собственный ключ. Сохраните независимую резервную копию в менеджере паролей или другом защищённом хранилище. Потерянный ключ нельзя восстановить из GitHub Secret, ciphertext или DNS API. Удаление state и генерация нового ключа не восстанавливают владение действующими записями. Поддерживается ручная [смена ключа](key-rotation.md); автоматического keyring нет.

## Новая установка

Сделайте Fork с **Copy the main branch only**; не копируйте чужую state branch. Добавьте свой ключ и свои DNS credentials. Первый явно разрешённый bootstrap создаст зашифрованное состояние для пустого DNS-назначения. Чужой ciphertext не принимается даже с совпадающим именем профиля.

После переименования или переноса репозитория прежняя привязка ciphertext перестанет совпадать. Перед такой операцией остановите writers и подготовьте отдельный проверенный перенос; автоматического перепривязывания нет.

## Перевод существующей установки

1. Оставьте `SMARTGATE_APPLY_ENABLED=false`, дождитесь завершения writers. Сохраните защищённые копии состояния и списка DNS-записей.
2. Старое состояние должно уже иметь schema 2 и точную привязку к DNS-назначению. Для schema 1 сначала завершите `state-upgrade` на прежней версии контроллера. Pending-журнал сначала восстановите; допускаются закрытые `verified`, `rolled_back` или отсутствие журнала.
3. Подготовьте Secret и резервную копию ключа, затем обновите код. Обычные команды новой версии отвергают незашифрованное Git-состояние.
4. На default branch запустите **`state-encrypt`, `apply=false`, `bootstrap=false`**. Preview читает старое состояние и проверяет владение через DNS API.
5. После проверки разрешите **`state-encrypt`, `apply=true`**. Команда сохраняет тот же документ в зашифрованном виде через CAS и проверяет точный новый commit. DNS-записи не изменяются. При неопределённом результате сначала выясните текущий head; не повторяйте запись вслепую.
6. Выполните защищённый `sync` с `apply=true`, `bootstrap=false`, `require_no_change=true`; ненулевой план и pending-журнал блокируются до записей. При нулевом плане DNS-операций нет, но контроллер может сохранить обновлённые metadata маршрутов, источники и курсоры проверок. Восстановление обычного расписания — отдельное решение после приёмки.

## Чтение подробного отчёта

Скачайте artifact нужного запуска, установите ключ в локальную переменную окружения `SMARTGATE_STATE_ENCRYPTION_KEY` и выполните:

```text
python -m smartgate report-decrypt --input report.enc.json --output private-report.json --repository OWNER/REPO --run-id RUN_ID --run-attempt ATTEMPT
```

Команда не обращается к DNS или GitHub, проверяет привязку и не перезаписывает существующий файл. Содержимое выводится только в явно указанный файл. Храните расшифрованный JSON вне репозитория; его нельзя прикладывать к публичным Issues без самостоятельного удаления приватных данных.

Локальные live-команды с Git state также используют приватные отчёты. Помимо credentials и ключа задайте `GITHUB_REPOSITORY`, `GITHUB_RUN_ID` и `GITHUB_RUN_ATTEMPT` для привязки артефакта. Actions задаёт их автоматически. Offline fixtures и `validate` не требуют ключа.

## Перед открытием репозитория

Шифрование защищает новые записи. Старые коммиты с plaintext state, прежние Actions logs, Summary и artifacts могут оставаться доступными согласно своим правам и срокам хранения. Git-объекты могут сохраняться и быть доступны по известному SHA после удаления ветки или переписывания истории. Простого удаления файла или ветки недостаточно для доказательства удаления старого содержимого. До перехода в public отдельно проверьте историю, старые запуски, artifacts и все копии. Очистку истории выполняйте только после защищённого backup и проверки recovery.

Шифрование не скрывает публичные исходники, конфигурацию, каталог сервисов и manifest, агрегаты отчёта, время запусков, размеры ciphertext и имена файлов. Envelope содержит открытые format/version/algorithm и nonce; привязка AAD задаётся доверенным контекстом при чтении, а не извлекается из ciphertext. Доверенный редактор workflow или скомпрометированный runner, получивший Secret, может прочитать данные. AES-GCM не предотвращает возврат администратора к старому валидному ciphertext; проверки CAS, DNS binding и API read-back остаются необходимыми.
