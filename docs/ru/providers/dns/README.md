# DNS-провайдеры

DNS и relay выбираются независимо. DNS отвечает устройству, куда подключаться; relay передаёт трафик. SmartGate проверяет маршруты, строит ограниченный план изменений, сохраняет владение записями и подтверждает результат через API и DoH.

## Выбор адаптера

| Адаптер | Подключение | Готовность | Рабочий apply |
| --- | --- | --- | --- |
| [NextDNS](nextdns.md) | API key + профиль; адреса API/DoH задаёт binding | Контрактные и изолированные live-проверки пройдены | Разрешён после настройки и проверки своего профиля |
| [AdGuard Home](adguardhome.md) | HTTPS API + Basic login/password + выделенный scope + DoH | Reference, локальные HTTP-тесты; live/ownership не подтверждены | Заблокирован |
| [Technitium](technitium.md) | HTTPS API + Bearer token + существующая зона + DoH | Reference, локальные HTTP-тесты; live/ownership не подтверждены | Заблокирован |

Два reference-адаптера показывают разные методы подключения и локально проверенные API-контракты. Даже успешный изолированный live-тест не изменяет их встроенный запрет production apply. Они не обещают готовую замену управляемого DNS: отсутствие постоянных ID, exact/subtree-семантика и другие типы DNS требуют отдельной проверки на вашем сервере.

## Настройки

Схема 2 разделяет `dns.provider` / `instance_id`, `dns.connection`, `dns.auth` и `dns.verify`. Общие переменные используют `SMARTGATE_DNS_*`. API key нужен способам `api_key` и `bearer`; Basic использует username/password. Настройки чужих адаптеров не требуются.

Примеры находятся в [config/dns](../../../../config/dns). GitHub Actions всегда читает [smartgate.actions.toml](../../../../config/smartgate.actions.toml); для смены адаптера перенесите в него соответствующие блоки DNS из примера и настройте нужные env. Такая смена требует проверки назначения и ownership state; локальная установка Python пользователю для развёртывания не нужна. Endpoint должен использовать HTTPS с действительным сертификатом. API auth никогда не передаётся в DoH или relay.

## Собственный VPS

На своём VPS можно разместить DNS, relay или контроллер. Это разные роли. Два VPS возможны для разделения DNS и зарубежного relay, но не являются обязательным количеством серверов. SmartGate нужен и собственной инфраструктуре: он проверяет маршруты и управляет сменой адресов, безопасным применением и восстановлением.

## Новый адаптер

Число адаптеров не ограничено архитектурой. Для каждого сервера нужен binding его API, авторизации, scope, record identity и проверяемых возможностей. [Шаблон адаптера](adapter-template.md) описывает контракт и критерии готовности. Новый адаптер регистрируется явно; произвольные плагины из конфигурации не импортируются.
