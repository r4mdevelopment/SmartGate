# Первый запуск

### Запустите SmartGate за 6 шагов

Самый простой вариант — **GitHub Actions + NextDNS + GeoHide**. Он уже настроен в репозитории: свой сервер для начала не нужен. SmartGate будет проверять адреса GeoHide и записывать подходящие маршруты в **ваш** DNS-профиль.

**Что понадобится:** аккаунты GitHub и NextDNS, отдельный пустой DNS-профиль и устройство для проверки. Контроллер работает в GitHub Actions — постоянно держать компьютер включённым не требуется. Для чтения подробного зашифрованного плана пока нужен Python на доверенном устройстве; [инструкция расшифровки](../operations/privacy.md#чтение-подробного-отчёта).

#### 1. Сделайте свою копию

Нажмите **Fork**, оставьте **Copy the main branch only** и создайте репозиторий. Все следующие действия выполняйте **в своей копии**. Откройте **Actions** и включите workflows, если GitHub предложит это сделать.

Чужую ветку `smartgate-state` копировать не нужно: SmartGate создаст свою при первом применении.

#### 2. Подготовьте DNS-профиль

Зарегистрируйтесь в [NextDNS](https://my.nextdns.io/) и создайте **отдельный профиль без DNS rewrites** — правил подмены адресов. Сохраните его **ID** со страницы **Setup** и свой **API key** из настроек аккаунта.

Пока оставьте DNS устройства прежним. Сначала SmartGate должен подготовить и проверить новые адреса.

#### 3. Добавьте настройки в GitHub

В своей копии откройте **Settings → Environments → New environment**, назовите окружение **`smartgate`** и добавьте:

| Куда добавить | Имя | Что указать |
| --- | --- | --- |
| Environment secret | `SMARTGATE_DNS_PROFILE_ID` | ID вашего нового DNS-профиля |
| Environment secret | `SMARTGATE_DNS_API_KEY` | API key вашего аккаунта NextDNS |
| Environment secret | `SMARTGATE_STATE_ENCRYPTION_KEY` | Собственный ключ шифрования: 32 случайных байта в Base64 |
| Environment variable | `SMARTGATE_APPLY_ENABLED` | `false` — расписание пока только проверяет маршруты |

Ключ шифрования защищает состояние и подробные отчёты. Подготовьте его по [инструкции](../operations/privacy.md#подготовьте-ключ) и сохраните независимую копию в менеджере паролей. DNS API key и ключ шифрования — **два разных секрета**.

Начальная конфигурация уже использует NextDNS и GeoHide. Для этого варианта менять провайдеров в файлах не нужно.

#### 4. Посмотрите, что будет изменено

Откройте **Actions → SmartGate sync → Run workflow**. Выберите **default branch** своей копии (обычно `main`) и параметры:

| Поле | Значение |
| --- | --- |
| `command` | `preview` |
| `apply` | `false` — флажок снят |
| `bootstrap` | `false` — флажок снят |
| `require_no_change` | `false` — флажок снят |

После завершения откройте **Summary**: там видны результат, количество планируемых изменений и проверки доступности. Этот запуск **не записывает DNS-правила и состояние**. **Перед первым применением** [скачайте и расшифруйте подробный отчёт](../operations/privacy.md#чтение-подробного-отчёта): проверьте, какие домены и адреса будут добавлены. Summary показывает только сводные числа, поэтому для проверки самого плана нужен этот отчёт. Локальное чтение отчёта — отдельное действие; контроллер продолжает работать в GitHub Actions.

**Если первый план превышает 20 изменений:** откройте [`config/smartgate.actions.toml`](../../../config/smartgate.actions.toml) в своей копии и временно увеличьте `max_mutations` до числа, достаточного для проверенного плана. Например, для 25 новых правил достаточно **30**. Сохраните изменение на default branch своей копии и повторите `preview` с `apply=false`, `bootstrap=false`. Это защита от большой партии изменений, а не лимит использования ChatGPT.

При ошибках или блокировке сначала разберите причину по [инструкции Actions](../operations/actions.md#ручные-запуски).

#### 5. Создайте DNS-правила

После проверки плана снова откройте **Run workflow** на **default branch** своей копии:

| Поле | Значение |
| --- | --- |
| `command` | `sync` |
| `apply` | `true` — флажок установлен |
| `bootstrap` | `true` — только для первого запуска на пустом профиле |
| `require_no_change` | `false` — флажок снят |

Теперь SmartGate создаст правила в выбранном профиле, проверит DNS-ответы и сохранит зашифрованное состояние в отдельной ветке. Дождитесь успешного результата и прочитайте предупреждения в **Summary**. Если запуск завершился ошибкой, изучите [порядок действий](../operations/runbook.md) перед повторным применением.

После первого успешного применения верните `max_mutations` к **20**, если повышали его. Для следующих обычных синхронизаций используйте **`bootstrap=false`**.

**Проверьте повторный запуск без изменений:** выберите `command=sync`, `apply=true`, `bootstrap=false` и **`require_no_change=true`**. Этот режим сверяет сохранённое состояние и DNS, но не разрешает создавать, заменять или удалять DNS-правила. Дождитесь успешной проверки с нулём изменений. Если появился новый план, запуск остановится: разберите его по [инструкции](../operations/actions.md#проверка-без-изменений-dns) перед включением расписания.

#### 6. Подключите устройство и проверьте доступ

В NextDNS откройте **Setup** своего профиля и следуйте инструкции для устройства. На Android в поле **«Частный DNS»** используется имя вида **`YOUR_PROFILE_ID.dns.nextdns.io`**, без `https://`. Для клиента с поддержкой DNS-over-HTTPS используется **`https://dns.nextdns.io/YOUR_PROFILE_ID`**. Подставьте **свой** ID.

Откройте ChatGPT и проверьте страницу, вход, отправку сообщения, загрузку и скачивание файла. Ожидаемый результат — сервис работает через ваш DNS-профиль. [Проверка подключения и функций](device-check.md).

После успешного повторного запуска без изменений и проверки устройства можно включить обновление маршрутов по расписанию: в Environment `smartgate` измените **`SMARTGATE_APPLY_ENABLED` на `true`**. SmartGate будет запускаться каждые 6 часов; запуск GitHub может задерживаться. При `false` расписание выполняет `doctor`: проверяет маршруты и DNS управляемых записей, не меняя DNS и состояние. До первого успешного bootstrap такой запуск может завершиться `degraded`, потому что ещё нечего подтвердить; он не создаёт правила автоматически.

**Готово:** DNS-провайдер отвечает вашему устройству, relay передаёт трафик, а SmartGate поддерживает маршруты в актуальном состоянии.
