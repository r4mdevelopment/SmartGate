# Проверка доступа с устройства

Профильные DNS-ответы и TLS со стороны контроллера — предварительные проверки. Готовность сервиса подтверждается отдельным тестом приложения из сети пользователя.

## Перед подключением

Дождитесь успешного ручного применения и проверки DNS в Actions. Используйте отдельное тестовое устройство, сохранив его прежние DNS-настройки для возврата. Не меняйте единственный рабочий компьютер, пока новый маршрут не проверен.

Откройте Setup своего профиля на [NextDNS](https://my.nextdns.io/) и выберите инструкцию для ОС устройства. Используйте адрес именно этого профиля: DoH, DoT либо выданный конфигурационный профиль. Общий IP NextDNS без привязки не подтверждает использование нужных rewrites.

Инструкции ниже описывают начальный вариант с NextDNS. Для другого DNS-провайдера используйте выданные им адреса и способ подключения. Везде заменяйте `PROFILE_ID` на ID своего профиля; API key и ключ шифрования на устройство вводить не нужно.

Следуйте инструкции Setup вручную. Обратите внимание на встроенный DNS браузера, VPN и приложения со своим resolver: они могут обращаться к другому профилю. Не меняйте несколько устройств одновременно.

## Android

Сохраните текущее значение «Частного DNS» на тестовом устройстве. В настройках найдите «Сеть и интернет → Частный DNS» и выберите hostname провайдера. Точный путь зависит от производителя; см. [справку Android](https://support.google.com/pixelphone/answer/2819583).

На странице Setup своего NextDNS-профиля скопируйте DNS-over-TLS hostname в поле провайдера. Это имя вида `PROFILE_ID.dns.nextdns.io`, а не URL с `https://`. Сохраните настройку и подтвердите подключение своего профиля на странице Setup с этого телефона.

Если система не может подключиться к провайдеру или интернет пропал, верните прежнее значение. Сбой подключения к DNS проверяется отдельно от ошибки ChatGPT. Укажите в результате, использовались Wi-Fi или мобильные данные.

## Windows

### Windows 11: встроенный DNS-over-HTTPS

1. На странице **Setup** своего профиля выберите Windows и сохраните адреса DNS-серверов и HTTPS-шаблон вида `https://dns.nextdns.io/PROFILE_ID`.
2. Откройте **Параметры → Сеть и Интернет**, выберите активное подключение Ethernet или Wi-Fi и его свойства. Рядом с **Назначение DNS-сервера** нажмите **Изменить**. Сохраните прежние значения; назначение IP-адреса менять не требуется.
3. Выберите **Вручную**, включите IPv4 и введите предпочтительный и альтернативный DNS из Setup. Для каждого выберите **DNS через HTTPS → Включено (шаблон вручную)** и вставьте HTTPS-шаблон своего профиля. Отключите возврат к незашифрованному DNS, чтобы сбой DoH не переключал запросы незаметно.
4. Если подключение использует IPv6, настройте и его DNS по адресам из Setup с тем же профильным HTTPS-шаблоном. Настройка только IPv4 может оставить запросы через другой DNS по IPv6.
5. Сохраните изменения и выполните [проверку подключения](#как-убедиться-что-подключён-нужный-dns). Названия полей могут отличаться между версиями Windows.

**Возврат:** восстановите прежние значения DNS на этом подключении; выберите **Автоматически (DHCP)** только если так было до теста. При необходимости очистите DNS-кеш:

```powershell
ipconfig /flushdns
```

Встроенная настройка DoH описана в [справке Microsoft](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/essential-network-settings-and-tasks-in-windows).

### Windows 10 или отсутствие настройки DoH

Откройте раздел Windows на странице **Setup**, установите предложенный там клиент NextDNS, укажите свой `PROFILE_ID` и включите подключение. В Windows 10 встроенной настройки DoH нет. После подключения проверьте профиль.

**Возврат:** выключите подключение в клиенте, при необходимости удалите его и восстановите сохранённые DNS-настройки. Обычный ввод IP DNS без привязки к профилю не заменяет этот способ.

## Linux

Для Ubuntu/Debian и других поддерживаемых дистрибутивов удобен [официальный клиент NextDNS](https://github.com/nextdns/nextdns/wiki/): он передаёт системные DNS-запросы через HTTPS. Это клиент DNS на тестовом устройстве; сам SmartGate продолжает работать в Actions.

1. Сохраните текущие настройки DNS и используйте [инструкцию для своего дистрибутива](https://github.com/nextdns/nextdns/wiki/). Для Ubuntu/Debian доступно [отдельное руководство](https://github.com/nextdns/nextdns/wiki/Debian-Based-Distribution).
2. Скачайте и запустите официальный установщик. Он устанавливает сторонний клиент и может запросить права администратора:

   ```bash
   curl -fsSL https://nextdns.io/install -o /tmp/nextdns-install.sh
   sh /tmp/nextdns-install.sh
   ```

3. Выберите установку, укажите свой `PROFILE_ID` и разрешите использование клиента для системного DNS на этом устройстве. Режим настройки роутера для проверки компьютера не нужен.
4. Выполните [проверку подключения](#как-убедиться-что-подключён-нужный-dns). Если сетью управляет NetworkManager или systemd-resolved, следуйте замечаниям установщика для вашей системы; редактировать `/etc/resolv.conf` вслепую не требуется.

**Возврат:** отключите использование клиента и остановите его:

```bash
sudo nextdns deactivate
sudo nextdns stop
```

Для полного удаления повторно запустите установщик и выберите **Uninstall**, затем проверьте прежние настройки DNS. Простая остановка службы не исключает её запуск после перезагрузки.

## macOS

1. В **Setup** своего профиля выберите macOS и создание конфигурационного профиля либо откройте [официальный генератор](https://apple.nextdns.io/). В поле **Profile** укажите свой `PROFILE_ID` и скачайте `.mobileconfig`.
2. Откройте скачанный файл, затем **Системные настройки → Основные → Управление устройством**. В разделе загруженных профилей выберите NextDNS, проверьте настройки и установите профиль. Путь в старых версиях macOS может отличаться.
3. Выполните [проверку подключения](#как-убедиться-что-подключён-нужный-dns) и сценарии выбранного сервиса.

**Возврат:** удалите именно добавленный для теста профиль в том же разделе, восстановите прежние настройки при необходимости и проверьте подключение. Подробности установки приведены в [инструкции NextDNS для Apple](https://apple.nextdns.io/).

## iPhone и iPad

1. Откройте в Safari страницу **Setup** своего профиля или [генератор профиля NextDNS](https://apple.nextdns.io/), укажите свой `PROFILE_ID` и скачайте `.mobileconfig`.
2. Откройте **Настройки → Профиль загружен** и установите профиль, проверив его содержимое. Если этот пункт не появился, найдите профиль в **Основные → VPN и управление устройством**. Для установки может потребоваться код-пароль устройства.
3. Выполните [проверку подключения](#как-убедиться-что-подключён-нужный-dns) сначала по Wi-Fi, затем отдельно по мобильной сети, если она используется. Профиль рассчитан на работу в разных сетях; VPN и настройки сети могут повлиять на фактический DNS.

**Возврат:** в **Настройки → Основные → VPN и управление устройством** выберите добавленный профиль NextDNS и удалите его, затем проверьте прежнее подключение. [Установка и удаление профилей: Apple](https://support.apple.com/en-gb/guide/iphone/iph6c493b19/ios).

## Как убедиться, что подключён нужный DNS

Откройте **Setup** своего профиля с проверяемого устройства: страница должна подтвердить использование именно вашей конфигурации. Дополнительно можно открыть [диагностику NextDNS](https://test.nextdns.io/); её результат содержит сведения о текущем подключении.

Проверка в браузере подтверждает путь DNS этого браузера. Чтобы проверить системную настройку через браузер, выберите в нём использование системного DNS. Если вместо этого браузер использует собственный DoH, даже с тем же профилем, результат подтверждает только его подключение. VPN и отдельные приложения могут использовать другой DNS; работу нужного приложения нужно проверить отдельно.

Если страница показывает другой профиль или отсутствие привязки, сначала исправьте подключение. Успешное открытие сайта само по себе не доказывает, что он работает через SmartGate.

## Что проверить

Зафиксируйте дату, устройство/ОС, браузер или приложение, тип сети и активный relay provider, затем проверьте:

| Сценарий | Результат |
| --- | --- |
| Профиль NextDNS подключён и отвечает | Не проверено |
| Страница ChatGPT загружается | Не проверено |
| Вход в аккаунт | Не проверено |
| Отправка сообщения и streaming ответа | Не проверено |
| Загрузка файла | Не проверено |
| Получение/скачивание файла | Не проверено |

Используйте свой аккаунт самостоятельно. Не передавайте cookies, пароли или содержимое приватных файлов в отчёт. Для проверки файла подойдёт небольшой нейтральный документ.

При сбое укажите сценарий, время и hostname ошибки, если он виден. Успешный root TLS не доказывает корректную авторизацию и ресурсы на других доменах. HTTP 403 автоматическому запросу без аккаунта также не равнозначен проверке браузера.

## Возврат и завершение

Если доступ нарушен, верните сохранённые настройки устройства и проверьте прежний resolver. DNS-кеши и открытые соединения могут удерживать прежний IP; повторите тест после их обновления средствами ОС.

Автоматическое применение включают отдельно только после ручного apply, повторного no-op, DNS и всех нужных сценариев приложения. До этого `SMARTGATE_APPLY_ENABLED` остаётся `false`.
